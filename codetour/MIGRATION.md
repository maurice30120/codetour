# Migrating from microsoft/codetour to CodeTour IA

[CodeTour IA](https://github.com/maurice30120/codetour) is an actively
maintained fork of [microsoft/codetour](https://github.com/microsoft/codetour).
The upstream project has been unmaintained since August 2025. This fork carries
the extension forward and adds AI-generated tours.

## Compatibility

Existing tours remain supported, with command links requiring migration:

- **`.tour` files** — the file format is unchanged. The schema was only
  extended with optional fields (`baseRef`, `baseFile`, `display`), so every
  existing tour loads as-is, including tours recorded with the original
  extension.
- **Command links** — replace `command:codetour.` with `command:codetourIA.`
  in tour descriptions, and `codetour.` with `codetourIA.` in step `commands`
  arrays and custom keyboard shortcut command IDs. For example,
  `codetour.startTour` becomes `codetourIA.startTour`. Legacy command aliases
  are not registered, to avoid conflicts with the original extension.
- **Default keyboard shortcuts, settings and tours stored in `.tours/`** — unchanged.
- **Public tour export and tour-by-URL links** — unchanged.
- **MCP clients** — broken on purpose. See
  [The MCP server is gone](#the-mcp-server-is-gone).

## What the fork adds

| Feature | Upstream | CodeTour IA |
| --- | --- | --- |
| Recording and playing back tours | Yes | Yes |
| AI-generated tours (agent skill + local CLI) | No | Yes |
| Changes Tour in reproducible Git diffs | No | Yes |
| `workspacePath` for multi-project workspaces | No | Yes |
| Mermaid diagrams in tour descriptions | No | Yes (validated offline) |
| Hardened anchor validation (ReDoS, symlink races, commit-tree anchors) | No | Yes |
| Actively maintained | No (since August 2025) | Yes |

Tours are generated by an AI agent that runs the CodeTour generation skill and
the local `codetour create-project-tour` / `create-changes-tour` commands. The
CLI validates the proposal, applies the workspace, Git, image and Mermaid rules,
and writes the Tour atomically. It is confined to the workspace you name, works
fully offline, and never touches the network. Full contracts:
[packages/tour-generation/README.md](packages/tour-generation/README.md).

## How to switch

CodeTour IA is not published on the VS Code Marketplace yet. Releases are
distributed as VSIX packages on
[GitHub Releases](https://github.com/maurice30120/codetour/releases).

1. Uninstall the original CodeTour extension (`vsls-contrib.codetour`) to
   avoid duplicate menus and competing playback surfaces.
2. Download the latest `.vsix` from
   [GitHub Releases](https://github.com/maurice30120/codetour/releases).
3. Install it:

   ```bash
   code --install-extension codetour-<version>.vsix
   ```

4. Reload the window. Your tours are picked up exactly as before.

### The MCP server is gone

CodeTour no longer ships an MCP server, and this is a breaking change for every
MCP client that used it. The removal is deliberate: generation is one command
invocation, so it needs a skill and a local CLI, not a long-lived transport.

What stops working:

- **`codetour mcp`** — the subcommand is removed; the CLI only reads, plays and
  creates (`codetour create-project-tour`, `codetour create-changes-tour`).
- **The `codetour` MCP server** — the `codetour` npm package is retired, and the
  VS Code extension no longer registers a server definition provider. A client
  that configured the stdio server by hand loses it.
- **The `create_project_tour` / `create_changes_tour` tools and the
  `codetour://review/critical-instructions` resource** — there is no MCP surface
  to call. The critical-review method now travels with the generation skill.
- **The Codex commands** — `CodeTour IA: Configure MCP for Codex` and
  `CodeTour IA: Repair MCP Configuration for Codex` are removed with the server
  they registered.

The replacement, for every client:

1. install a supported agent with `codetour --install` (`copilot`, `pi`); the
   install writes the generation skill and its critical-review pack;
2. let the agent follow that skill: it explores the workspace and hands a JSON
   proposal to the CLI;
3. or call the CLI yourself, from the workspace root:

   ```sh
   codetour create-project-tour --workspace <dir> --proposal proposal.json
   codetour create-changes-tour --workspace <dir> --proposal proposal.json
   ```

### Migrate an existing installation

`codetour --install <agent>` and `codetour --uninstall <agent>` remove what this
release retires and CodeTour can prove it owns:

- the MCP-routed Copilot adapter in `<COPILOT_HOME>/extensions/codetour`, file by
  file, only when its bytes match the release that wrote it;
- the `codetour` plugin, through `copilot plugin uninstall codetour`, so the
  plugin's retired `mcp.json` goes with the host-owned cache;
- the `codetour` entry of `<COPILOT_HOME>/mcp-config.json` when it matches one of
  the two launch shapes an older CLI wrote (`codetour mcp`, or the absolute Node
  launcher of the installing CLI with `mcp`);
- the retired `skills/codetour-knowledge` directory;
- the guarded run states of the current workspace
  (`<workspace>/.tours/.log/codetour-run-*.json`) that satisfy the retired
  on-disk contract.

Everything else is reported and left alone: a modified or foreign file, a
same-named server launched another way, a corrupt run state, and — because
CodeTour cannot reach it — the configuration an older release wrote into Codex.
`codetour --doctor` lists those leftovers with the command to remove them:

```sh
codex mcp remove codetour      # the Codex-side configuration of a removed server
```

No Tour is touched: `.tours/*.tour`, `.tours/images/` and the creation journal
under `.tours/.log/creations/` are never removed or rewritten by a migration, so
Tours written before this change still open with `codetour <title>`, the HTML
renderer and the VS Code extension.
