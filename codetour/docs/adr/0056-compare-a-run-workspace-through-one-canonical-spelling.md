# Compare a generation run's workspace through one canonical spelling

A CodeTour generation run is identified on disk by `workspace`, `sessionId` and `runId`: the MCP server writes the Tour and its consolidation closure into `<workspace>/.tours/.log/codetour-run-<runId>.json`, and the Copilot `agentStop` hook and the Pi guard read it to decide whether the run still owes a consolidation. We decide that the `workspace` field carries the **canonical** spelling of the root — resolved, native real path, trailing separator removed — and that every comparison between a state and a caller's root goes through the same rule.

**Why a rule at all.** Two spellings of one directory are the norm: a `..`-composed or symlinked path, a trailing separator, a mapped drive, and — the case that made this decision necessary — an 8.3 short name on Windows. Node ships **two** realpath implementations with different answers: `fs.realpathSync` keeps `C:\Users\RUNNER~1\...`, while `fs.promises.realpath` answers the native long form `C:\Users\runneradmin\...` (the latter is documented as `fs.realpath.native` semantics). A server writing with one and a hook comparing with the other never agree, the hook silently treats the run as someone else's, and the consolidation guard stops asking for its one continuation.

**Why the canonical form is written, not only compared.** A writer that stores whichever spelling it was handed leaves every later reader to rediscover the equivalence, including readers that are not ours (an older plugin copy, a diagnostic, a hook from another release). One spelling on disk, produced by one rule, removes the equivalence problem from the reading side: the state names the root the file system itself would name.

**Why comparisons stay tolerant.** Existing states were written with whatever spelling their surface used, and a state can be produced by a surface this release does not control. The comparison therefore canonicalises *both* sides before comparing, so a legacy or foreign spelling still matches, and no migration has to run on the reader's files. Tolerating a second spelling is not tolerating a second workspace: two different roots stay different, because the canonical form is derived from the file system, not from string trimming.

Considered and rejected: comparing after trimming separators and lowering the case (a Windows-shaped rule that would make two genuinely distinct roots equal on that platform alone); migrating every state file at read time (a write on a read path, under a lock, for files that the tolerant comparison already handles); keying the run state by a hash of the root (an opaque identity the hook cannot print or debug, for no gain over the canonical string).

Consequence: `packages/knowledge` owns the rule (`canonicalWorkspacePath`, `sameWorkspace`), the extension and the terminal reader import it through `src/core/workspacePath.ts`, the MCP server uses it for the root it records, and the JavaScript surfaces — the Copilot extension, the generated plugin copy and the Pi package — carry a mirrored `canonicalWorkspace`/`sameWorkspace` pair that the existing sync test keeps aligned. A machine-specific spelling difference is therefore a configuration detail, never a lost run.
