# AI-Generated Code Tours

This context defines the guided explanations generated by an AI agent to help developers understand a codebase or a set of changes.

## Language

**Project Tour**:
A guided explanation of a codebase's purpose, structure, and important execution paths for a developer discovering the project.
_Avoid_: Global tour, architecture tour

**Changes Tour**:
A guided explanation of the intent, implementation, and impact of the committed changes on a branch since it diverged from its base. Uncommitted changes are excluded unless explicitly included.
_Avoid_: Change mode, diff tour, branch tour

**Tour**:
An ordered sequence of contextual explanations attached to relevant locations in a codebase.
_Avoid_: Walkthrough file, generated documentation

**Tour Step**:
One contextual stop in a Tour, anchored to a code location or content surface and carrying a description.
_Avoid_: Comment, slide

**Tour Anchor**:
A stable location in the codebase that associates a Tour step with the code or directory it explains.
_Avoid_: Pointer, target

**Tour Generator**:
An AI agent that analyzes a workspace and proposes a Project Tour or Changes Tour through CodeTour's MCP tools.
_Avoid_: MCP client, tour writer

**Mermaid Diagram**:
A visual explanation whose Mermaid source is embedded in a Tour's explanatory Markdown and rendered by CodeTour for the reader.
_Avoid_: Schema, generated image

**Tour Workspace**:
The single project directory that a Tour Generator is allowed to inspect and in which generated Tours are persisted.
_Avoid_: Workspace root argument, current folder

**Playback Surface**:
A user-visible place where a Tour or Tour Step description is presented while reading a Tour.
_Avoid_: Component, container

**Expanded Description View**:
The side panel displaying the active Tour Step's explanation while the code retains its anchor marker.
_Avoid_: Prototype, variant A

**Tour Step Draft**:
An unsaved change to a Tour Step's explanation.

**Tour Step Conversation**:
A discussion with an agent about one Tour Step, grounded in its displayed code and explanation. Each step has its own conversation.
_Avoid_: Tour chat, workspace chat

**Step Narration**:
The optional local text-to-speech rendering of the active Tour Step's description while reading, off by default and never advancing the Tour.
_Avoid_: Voiceover, audio tour, TTS playback

**Targeted Context**:
A bounded selection of code symbols and locations relevant to a Tour, offered to the Tour Generator as a substitute for open-ended exploration. Off by default; a Tour Generator without it behaves as if it never existed.
_Avoid_: Repository Map, optimisation, context map

**Research Harness**:
The `codetour-research` command that investigates one Research Question in a workspace and returns structured, source-referenced findings to the calling agent.
_Avoid_: Black box, explorer, research tool

**Research Question**:
One question about a single mechanism or execution path, delegated to the Research Harness and naming the directories or files to examine when they are known.
_Avoid_: Prompt, objective, multi-part question

**Memory Function**:
A reusable, validated search procedure persisted by the Research Harness under a stable name for later runs of similar Research Questions.
_Avoid_: Procedure, script, learned skill

**Memory Method**:
A reusable search method expressed as short instructions for the Research Harness agent to interpret while investigating a Research Question. It is read, never executed.
_Avoid_: Micro-skill, skill, Memory Function, executable script

**Memory Entry**:
A reusable item persisted in a workspace's `.tours/.memory/`: a Memory Function, a Memory Method, or — in the experimental Knowledge mode only — a hand-prepared Knowledge Entry under `.tours/.memory/knowledge/`. Only a Consolidation Run creates Memory Functions and Memory Methods; Knowledge Entries are prepared manually (spec #219).
_Avoid_: Skill, compétence

**Memory Catalogue**:
The set of Memory Entries stored in a workspace's `.tours/.memory/`, discoverable by description without loading their content.
_Avoid_: Memory dump, function library

**Knowledge Entry**:
One hand-prepared Markdown file of the experimental Knowledge mode (spec #219), stored under `.tours/.memory/knowledge/`: a name, a description and SHA-256 evidence proofs in frontmatter, and a body the Research Harness returns only after verifying every declared proof. Not a new memory kind: the durable vocabulary (ADR 0035, ADR 0036) still calls this Markdown concept a Memory Method, created by a Consolidation Run; Knowledge Entry is the prototype's chosen name for it, an experimental exception recorded here without rewriting those decisions.
_Avoid_: Knowledge base, skill, document

**Knowledge Catalogue**:
The set of Knowledge Entries stored in a workspace's `.tours/.memory/knowledge/`, a fixed location under the hidden memory root, discovered by name and description without loading any body.
_Avoid_: Knowledge base, dump

**Knowledge Mode**:
The experimental Research Harness mode (`--knowledge`, spec #219) in which the Knowledge Catalogue is discovered by name and description only, `memory_read(name)` returns one validated body behind the existing Observation Masking, Memory Functions are unavailable, and no Consolidation Run runs. Exclusive of the historical Memory Function mode.
_Avoid_: Memory mode, hybrid mode

**Research Run**:
One execution of the Research Harness on a Research Question. It may use Memory Entries but never creates one.
_Avoid_: Tour (reserved for the guided explanation), research Tour

**Consolidation Run**:
The step that follows a validated Research Run and decides, for each reusable finding, whether to persist a Memory Function, a Memory Method, or nothing.
_Avoid_: Consolidation Tour, learning pass

**Observation Masking**:
Replacing older tool results in the history sent to the model with a one-line stub, so context stops growing with every call. Distinct from a summary or a truncation of a single result.
_Avoid_: Context pruning, history compaction
