# Scope the native deterministic Knowledge CLI against the hybrid Memory ADRs

Spec #223 makes one part of the experimental Knowledge contract native: an installable `codetour knowledge` CLI that discovers the catalogue, reads one entry behind the same deterministic evidence gate, and hashes workspace files for preparing evidence. It runs in any project, needs no network, no model and no API key, and never orchestrates a task; it reads and hashes files only. This ADR fixes how that boundary relates to ADR 0035, ADR 0036 and ADR 0038 without rewriting them.

**Against ADR 0035 (hybrid Memory Functions and Methods).** Native reading does not create a third Memory Entry kind and does not implement a Consolidation Run. The durable vocabulary stays: a Memory Function and a Memory Method are created only by a Consolidation Run, and deciding what is reusable remains that step's job. The native read surface serves Markdown context; it does not select, generate or persist Memory Entries. Persistence through a native deterministic writer is a separate, later ticket and, when it lands, writes the same `.tours/.memory/knowledge/` catalogue rather than redefining the kind.

**Against ADR 0036 (identifier-named files, harness as sole writer).** This ticket keeps the native CLI read-only, so the ADR's "the harness is the sole writer" rule is untouched in practice. The identifier-name convention is shared: `validateCanonicalName` is exported by the `codetour-knowledge` package and reused by the historical harness instead of duplicated. The single-writer rule is scoped to writers, not readers; a native reader over the same files does not violate it.

**Against ADR 0038 (experimental Knowledge mode).** That ADR describes the historical Research Harness experiment and its result, and stays historical: `--knowledge` and `--memory` keep working through unchanged harness behaviour, the experiment's exclusions and conclusions are not revised, and no historical Memory Function is removed. ADR 0038's phrase "the harness is the sole read gate" is narrowed to the experiment it governed. The native CLI is an additional read gate over the same catalogue, applying the same rule: every declared `file` proof must match the cited bytes' SHA-256 before a body is returned, and every refusal carries a reason but no body, cited path or hash. Validity still proves declared evidence matches; it never proves semantic correctness or completeness.

**Scope of the move.** The contract lives once, in `packages/knowledge` (`codetour-knowledge`): parsing, hashing, verification, catalogue discovery, deterministic persistence and the canonical-name rule. `packages/exploration-poc/src/knowledge.ts` is a thin re-export shim so the historical harness keeps its imports and tests. The packaged CLI is the outer seam: stable exit statuses (`0` success, `1` internal, `2` usage or unusable workspace, `3` absence, `4` invalid) and exactly one JSON object on stdout. The standalone artifact embeds the same module, so the installed binary and the checkout share one contract rather than two implementations.

**Update — ticket #225 (native writer).** `codetour knowledge save` adds the writer this ADR deferred. It implements the same decision: a proposal is validated in full — canonical names, one-line descriptions, non-empty Markdown bodies, at least one evidence proof per entry, every proof hashed with the read gate's own rules — before anything is written. Publication stages files in the catalogue directory and links them into place, so a name conflict or any invalid entry writes nothing and preserves the existing entry byte for byte; an empty proposal is an explicit `no-op`, not an omission. This narrows ADR 0036's "the harness is the sole writer" to the Memory Functions and Memory Methods a Consolidation Run creates: the native writer owns only Knowledge Entry files under `.tours/.memory/knowledge/`, never creates or runs a Memory Function and never performs a Consolidation Run. The API (`saveKnowledgeProposal`) and the CLI share it, so no divergent hash or conflict logic exists.

**Update — ticket #226 (native skill).** `codetour --install copilot` also writes the `codetour-knowledge` skill to the personal skills directory Copilot discovers (`~/.copilot/skills/codetour-knowledge/SKILL.md`, overridable with `CODETOUR_COPILOT_SKILLS_DIR`). The skill is distribution, not a new contract: it composes the CLI and MCP surfaces above, and the CLI bundle embeds its Markdown so the install needs no checkout. It does not add a read gate, a writer or a Consolidation Run. Its workflow treats a `valid` body as reference context, forbids re-reading every cited source and a second mandatory anchor pass (the MCP validates anchors), and asks for one explicit consolidation through `codetour knowledge save`. Two limits are part of the decision: the instruction is not an enforced guard, so nothing proves the consolidation ran, and evidence validity still proves only that declared evidence matches, never semantic correctness or completeness. The skill never invokes the Research Harness, never creates or runs a Memory Function and never needs a harness API key; ADR 0038's experiment and its artefacts remain historical and untouched. The historical `codetour-research` skill and Memory Functions are not modified.

**Update — Knowledge file names get their own rule.** Reviewing the native writer surfaced an overload: one name served two stakeholders, a TypeScript identifier for hand-authored Memory Files (ADR 0036) and a flat catalogue file name for Knowledge Entries. A Knowledge name is only a lookup key, never executed as code, so the shared identifier test is no longer the Knowledge contract. `validateCanonicalName` keeps governing the historical Memory Functions and Memory Methods exactly as before, while Knowledge Entries use `validateKnowledgeName` — a Unicode letter, digit, `_` or `$` to start, then those plus `-` — in the read gate, and `validateNewKnowledgeName`, the same rule plus a refusal of Windows device names, in the native writer. This supersedes the shared-convention sentences in the ADR 0036 and "Scope of the move" paragraphs above: paths, spaces, dots and option-looking names are still rejected, the read gate still confines every lookup to the flat catalogue directory on its own, existing catalogues stay readable untouched, and the split lives once in the `codetour-knowledge` package so the CLI, the MCP server and the harness all call the same contract.

**Scoped exception to ADR 0015 (French notice).** Spec #223 mandates one French sentence verbatim in the native skill's Knowledge notice — « La Knowledge suivante a été validée pour l’instantané de code étudié. Utilise-la comme contexte de référence pour créer le Tour. Complète-la par une exploration ciblée uniquement si elle ne suffit pas à couvrir la demande ou à construire les étapes. » This is a deliberate, scoped exception to ADR 0015's English-chrome rule: the wording is fixed by the spec, stays French, and must not be translated or reworded. The exception covers only that notice; every other user-facing string remains English per ADR 0015.

**Update — the standalone skill is retired (plugin era).** The Agent Plugins 1.0 plugin (ADR 0041) now composes the whole workflow: the served `generate_project_tour` prompt owns the Tour method, the MCP `knowledge_list` and `knowledge_read` tools own discovery and reference reads with verification before serving (failures reported under `invalid` with a machine-readable reason, ADR 0044), and `knowledge_save`/`knowledge_close_run` own consolidation, guarded by the plugin's `agentStop` hook. `codetour --install copilot` no longer writes `codetour-knowledge` and, like `--uninstall copilot`, removes a leftover `~/.copilot/skills/codetour-knowledge/` directory so an older install cannot load a second, CLI-first CodeTour skill next to the plugin. Other skills in the shared directory are untouched. The "#226 native skill" update above describes the retired artifact, and its store is gone from `packages/knowledge`: the native CLI commands this ADR defines remain, distribution included. The scoped French-notice exception to ADR 0015 ends with the skill; the served prompt keeps ADR 0015's English chrome.
