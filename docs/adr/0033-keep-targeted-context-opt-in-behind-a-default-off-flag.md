# Keep Targeted Context opt-in behind a default-off flag

Spec #92 gates every Targeted Context work behind a flag that is off by default, with the historical generation path proven unchanged while the flag is off. This ADR records that this default is the decision of record for V1, and that a proposed alternative — a hybrid generation prompt that embeds a targeted selection in every run — was examined and rejected.

The deciding criterion is the one spec #92 names as the product goal: the real cost, in tokens and money, per valid Tour. A design that prepares and sends a targeted selection systematically pays that cost on every generation, including the runs where the selection serves nothing; the flag converts the same preparation into a deliberate per-run choice. The selection contents stay as the implementation tickets define them: modified symbols plus useful neighborhood for Changes Tours (#115), architecture and entry points for Project Tours (#117), and progressive reads through the MCP server rather than full bodies (#116). When those tickets ship, the flag still defaults to off: turning it on remains a benchmark-triggered go/no-go (#118), never a silent deployment.

The rejected hybrid — always-embedded selection, simpler than specified, Git reads performed up front — had two flaws. It contradicts the non-regression requirement of #115 and #117, since the default path would no longer be the current pipeline. It also contaminates the benchmark: scenario A (historical) is the baseline of #118, and it is only meaningful if the default pipeline has measurably not moved. Weaker selection by default would measure a changed baseline against itself.

Consequences: #115, #116 and #117 keep their written scope and remain open, sequenced behind #113 and #114 as #92 orders them; this decision closes the divergence question in favor of the spec rather than superseding any of it. Any future change to the default is a new decision, taken on the measurements of #118.
