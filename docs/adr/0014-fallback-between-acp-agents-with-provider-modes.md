# Fall back between ACP agents using provider-specific modes

Tour Step Conversations try installed ACP agents in the order Vibe, Copilot, Codex, Claude Code, retaining the first working session until the reading view closes. A failed launch, authentication, handshake, mode negotiation or prompt before the first answer text falls back to the next provider; an interrupted request or a partially streamed answer never does, to avoid unwanted retries and mixed answers. Nothing is installed automatically.

This extends ADR 0013's Vibe-only Ask-mode requirement: select and track Vibe Ask, Copilot’s advertised default mode with a read-only tool allowlist, Codex read-only, or Claude Agent ACP Plan. These modes are provider policy, not an OS sandbox: preserve all client capability refusals, file confinement and tool permission checks from ADR 0013, and restrict Copilot's available tools to view, grep and glob with built-in MCP servers disabled. Vibe, Codex and Claude are skipped if their required mode is absent. Copilot always uses its advertised default without looking for Ask: the mode is tracked for drift, while tool filtering and permission refusal enforce the reader policy independently of its name. Startup has a bounded deadline for each provider, and the conversation shows the provider being tried.

Questions serialize the whole selection, startup, fallback and prompt operation on the shared session so concurrent step conversations cannot advance the same fallback index. Stopping invalidates queued questions and retires the active transport before fresh questions proceed; the selected provider is retained for restart. Closing the reading view additionally resets provider selection.
