## Installer sur la nouvelle machine

Utiliser la version Node déclarée dans `.nvmrc` et les dépendances verrouillées. Depuis la racine :

```sh
npm ci --prefix packages/exploration-poc
npm ci --prefix packages/exploration-sandbox
npm ci --prefix packages/vibe-connector
npm ci --prefix poc/benchmark/runner
npm ci --prefix poc/benchmark/evaluator
cp .env.local.example .env.local
chmod 600 .env.local
```

Renseigner `MISTRAL_API_KEY` localement. La clé reste dans le trousseau et dans le fichier local ignoré sur l'ancien Mac ; elle n'est ni dans le commit ni dans les archives. Le CLI et `poc/benchmark/config.ts` chargent `.env.local` automatiquement. Pour le précontrôle `.mjs`, utiliser explicitement `node --env-file=.env.local poc/benchmark/preflight.mjs`.

Installer et authentifier Vibe selon sa configuration propre. L'ancienne machine utilisait la CLI 3.1.2 ; relever la version réellement installée et les identités de modèle effectivement observées. L'alias configuré Medium ne garantit pas l'identité réelle du sous-agent natif (les traces rapportent `mistral-vibe-cli-latest` et un routage racine distinct). Les scripts de conservation des journaux archivés dépendent d'un chemin Python macOS et d'une API interne de Vibe ; ce sont des pièces de diagnostic, pas un lanceur portable validé.

Restaurer la fixture publique propre :

```sh
git clone https://github.com/postgres/postgres.git poc/benchmark/postgres
git -C poc/benchmark/postgres checkout --detach 70c4a57b64d39c526eb4c44a925eb92a6e56f3c5
git -C poc/benchmark/postgres status --porcelain
```

Si le dossier existe déjà, vérifier son HEAD et son arbre propre. Le runner refait cette vérification avant chaque run. Garder les mémoires et sorties hors de la fixture. Les chemins absolus et hashes de chemins réels des catalogues/sceaux archivés appartiennent à l'ancien poste : créer de nouveaux dossiers et une mémoire vide.
